# Full Marhl precision computation

This runner covers all **380 potential trajectories** needed to revisit the
twelve failed Marhl breaking cases, using **four requests per trajectory**:
1,520 integrations in total. The full untreated control and the 29 original
failed branch specifications come first. The other 350 trajectories remain
required. All 88 controls generated by the original conditional search are
included; none are removed because they were absent from a failed original run.

The [original inventory](../catalog-breaking-marhl-full-controls-20261118/README.md)
reproduces all 38 initial cases from the pinned evidence. It records the
original Linux result of 26 passing cases. This precision runner does not change
that result or recover cases merely by completing individual trajectories.

## What is computed

Between interventions the five concentrations satisfy the original BioModel 39
ODE, `dx/dt = f(x)`. An intervention replaces only the named concentrations at
the specified absolute time. It does not restart the clock or reset the other
coordinates. Histories, breaker exposures and final rechallenges retain the
original timing and values.

Every trajectory keeps its original 1,410, 1,810 or 2,210 time-unit horizon,
0.01 sampling interval, observations beside reset discontinuities, and all five
observables: `Ca_cyt`, `CaER`, `CaM`, `CaPr`, and `Pr`. The inventory pins each
complete sample grid and each train's reset count. The eight control arms
distinguish prior history, breaker exposure and final rechallenge; a numerical
match in one arm does not establish a complete controlled memory result.

| Request | Implementation | Precision | Truncation tolerance |
|---|---|---:|---:|
| `taylor128` | Heyoka, equations compiled from the original SBML | 128 bits | `1e-30` |
| `taylor192` | Heyoka, equations compiled from the original SBML | 192 bits | `1e-45` |
| `mpmath128` | Independently transcribed and model-checksummed equations | 128 bits, degree 32 | `1e-30` |
| `mpmath192` | Independently transcribed and model-checksummed equations | 192 bits, degree 48 | `1e-45` |

Both implementations use Taylor methods. They provide independent equation
implementations and precision refinement, not a claim of independent integrator
families. The original binary64 coefficients and reset values are promoted
exactly, so increasing arithmetic precision does not change the supplied model.

Each task retains an exact-state checkpoint, its full binary64 observation
array, integration counters, requests, implementation hashes and runtime
identity. Heyoka preserves the compensated clock and MPFR state. The mpmath
adapter uses fixed integration chunks of at most one time unit within physical
reset intervals and verifies exact decimal state round trips. Both resumed and
uninterrupted mpmath runs use the same chunk grid. Neither restarts from rounded
observation arrays.

Time budgets are cooperative: the current native chunk must finish before the
budget can be checked. A hard external termination can lose work since the last
checkpoint. A partial checkpoint is explicitly incomplete. Source, runtime,
protocol and task identities must remain unchanged on resume.

## Independent array audit

The auditor requires four completed tasks for one original branch. It verifies
the array and final checkpoint digests, their full observation equality, the
complete original time grid, every observable and reset count, and the original
numerical requests. It then recomputes all six pairwise comparisons at every
sample. The unchanged acceptance criterion is

```
abs(x - y) / (1e-7 + 2e-5 * max(abs(x), abs(y))) <= 1
```

The maximum discrepancy, its observable and time, and per-observable maxima
remain in the audit. Window means and ranges are recomputed with the original
sample-based definition for later case replay. An isolated late disagreement
therefore remains a mismatch even when almost all other samples agree.

Arrays contain binary64 observations. Array agreement does not prove equality
of internal high-precision states, global solution uniqueness, or biological
validity. All original conditional cases still require full replay after their
necessary branch outcomes are available.

## Reproduce the scope and run a task

From `python/`, create an isolated environment with uv. Heyoka's supported Linux
environment is also exercised by the validation workflow; existing numerical
worker environments are not modified.

```sh
uv venv .venv-marhl-precision --python 3.12.13
uv pip install --python .venv-marhl-precision/bin/python \
  -r environments/marhl-full-precision-requirements.txt

.venv-marhl-precision/bin/python -B scripts/run_marhl_precision.py check \
  --plan results/catalog-breaking-marhl-full-precision-20261119/plan.json

.venv-marhl-precision/bin/python -B scripts/run_marhl_precision.py run \
  --plan results/catalog-breaking-marhl-full-precision-20261119/plan.json \
  --task 0 --output results/marhl-task-0 --max-seconds 14400
```

An incomplete task exits with status 2 and preserves its report and checkpoint.
Use the same command with `--resume` to continue. A completed task is revalidated
and reused; an existing report cannot be silently overwritten as a fresh task.
The plan has six scheduling batches (five of 256 tasks, one of 240). Batching
does not change the complete 1,520-task requirement.

After tasks 0 through 3 complete, audit the full untreated control:

```sh
.venv-marhl-precision/bin/python -B scripts/run_marhl_precision.py audit \
  --plan results/catalog-breaking-marhl-full-precision-20261119/plan.json \
  --branch b5f70bd5bd9a3c6273555ba22992a27965f0794869348491cd29cef30854934c \
  --directory results/marhl-task-0 --directory results/marhl-task-1 \
  --directory results/marhl-task-2 --directory results/marhl-task-3 \
  --output results/marhl-baseline-audit.json
```

The historical inventory check requires Git objects
`079e35d8bc0795f427b6cb5b8514f35830f01909`,
`70a3afad61357e94873ff62a7300c099b4c7ae3e`, and
`2e7327b0d273f4b33bdd8aa37601c1a497854a2a`. The workflow fetches those exact
revisions in its shallow checkout.
